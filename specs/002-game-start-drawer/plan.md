# Implementation Plan: Game Start and Drawer Flow

**Branch**: `assignment` | **Date**: 2026-06-11 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-game-start-drawer/spec.md`

## Summary

Extend the game-start flow to assign the first-joined participant as the drawer, select
`"rocket"` as the deterministic secret word, and deliver the word only to the drawer via
the existing viewer-aware snapshot. Update the Game screen to render role labels and
conditionally display the word.

## Technical Context

**Language/Version**: TypeScript; Node.js 18+ (backend), Vite + React 18 (frontend)

**Primary Dependencies**: Express + Zod (backend); React hooks (frontend)

**Storage**: In-memory `Map<string, Room>` — no persistence

**Testing**: Vitest — existing suites in `backend/src/services/roomStore.test.ts`

**Target Platform**: Local dev, two-tab browser validation

**Project Type**: Brownfield web application

**Constraints**: Deterministic word index 0; no randomisation; no new libraries

## Implementation Sequence

### Phase A — Backend model

1. `backend/src/models/game.ts`
   - Add `drawerId?: string` and `secretWord?: string` to `Room`
     (optional so lobby rooms satisfy the type without these fields)
   - Add `drawerId?: string` and `secretWord?: string` to `RoomSnapshot`

### Phase B — Backend service

2. `backend/src/services/roomStore.ts`
   - `startRoom()`: after setting `status: "active"`, also set
     `room.drawerId = room.participants[0].id` and `room.secretWord = STARTER_WORDS[0]`
   - `startRoom()`: pass the caller's `participantId` to `toRoomSnapshot`
   - `toRoomSnapshot()`: remove `void viewerParticipantId`; include `drawerId` unconditionally
     (when set); include `secretWord` only when `viewerParticipantId === room.drawerId`

### Phase C — Frontend types

3. `frontend/src/services/api.ts`
   - Add `drawerId?: string` and `secretWord?: string` to `RoomSnapshot` interface

### Phase D — Frontend Game screen

4. `frontend/src/pages/GamePage.tsx`
   - Derive `isDrawer = participantId === room.drawerId`
   - In the Player Info card, replace the static "Playing" status with the derived role
     ("Drawer" or "Guesser")
   - Add a "Secret Word" display area: show `room.secretWord` if present (drawer),
     otherwise show `???` (guesser)
   - Add role labels to the participant list or scoreboard area so all players can see
     who is the drawer

## Testing Strategy

- Extend `backend/src/services/roomStore.test.ts`:
  - Verify `startRoom()` sets `drawerId` to `participants[0].id`
  - Verify `startRoom()` sets `secretWord` to `"rocket"`
  - Verify `toRoomSnapshot()` returns `secretWord` for the drawer
  - Verify `toRoomSnapshot()` omits `secretWord` for a non-drawer participant
- Manual validation per quickstart.md scenarios A–D

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| `toRoomSnapshot` called without `viewerParticipantId` in other paths | Audit all call sites; removing `void` makes missing-arg behaviour visible at code review |
| Host ≠ drawer (host is not always index 0) | Covered by Scenario D quickstart test; spec explicitly says first joiner = drawer |
| Optional fields on Room cause TS errors in existing lobby code | Lobby code never accesses `drawerId`/`secretWord`; optional typing prevents false positives |
