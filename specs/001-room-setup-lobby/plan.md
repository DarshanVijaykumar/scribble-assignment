# Implementation Plan: Room Setup and Lobby

**Branch**: `assignment` | **Date**: 2026-06-10 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-room-setup-lobby/spec.md`

## Summary

Extend the Scribble starter scaffold to support full room-lifecycle management: host tracking,
input validation, automatic lobby polling, host-only start controls, and a server-side
start-game transition. All synchronisation uses HTTP polling at ~2-second intervals; no
WebSockets are introduced.

## Technical Context

**Language/Version**: TypeScript; Node.js 18+ (backend), Vite + React 18 (frontend)

**Primary Dependencies**: Express + Zod (backend); React hooks + `useSyncExternalStore` (frontend)

**Storage**: In-memory `Map<string, Room>` in `backend/src/services/roomStore.ts`; no persistence

**Testing**: Vitest (both backend and frontend); existing test files in
`backend/src/api/schemas.test.ts` and `backend/src/services/roomStore.test.ts`

**Target Platform**: Local dev only; browser-based multi-tab validation

**Project Type**: Brownfield web application (frontend + REST backend)

**Performance Goals**: Polling at ~2-second intervals; no concurrent-load requirements for this lab

**Constraints**: No WebSockets; no database; no new routing/state libraries; in-scope changes only

**Scale/Scope**: Single-room, in-memory; 2–8 players per room

## Implementation Sequence

### Phase A — Backend: model + validation

1. `backend/src/models/game.ts`
   - Add `hostId: string` to `Room`
   - Add `hostId: string` to `RoomSnapshot`
   - Extend `RoomStatus` to `"lobby" | "active"`

2. `backend/src/api/schemas.ts`
   - Change `playerName` in both `createRoomSchema` and `joinRoomSchema` to
     `z.string().trim().min(1, "Player name is required")`
   - Add `startRoomSchema`: `z.object({ participantId: z.string().min(1) })`

3. `backend/src/services/roomStore.ts`
   - Update `createRoom()`: capture `participant.id` and set `hostId: participant.id` on the room
   - Update `toRoomSnapshot()`: include `hostId: room.hostId`
   - Add `startRoom(code, participantId)`:
     - Return `null` if room not found
     - Return `{ error: "forbidden" }` if `participantId !== room.hostId`
     - Return `{ error: "conflict" }` if `participants.length < 2`
     - Otherwise set `status: "active"`, call `saveRoom()`, return updated snapshot

### Phase B — Backend: start-game route

4. `backend/src/api/rooms.ts`
   - Add `router.post("/:code/start", ...)` handler
   - Parse `startRoomSchema` from request body
   - Call `startRoom(code.toUpperCase(), participantId)`
   - Map `null` → 404, `"forbidden"` → 403, `"conflict"` → 409
   - On success return `{ room: snapshot }`

### Phase C — Frontend: types + API

5. `frontend/src/services/api.ts`
   - Fix `API_BASE_URL` default: remove `/bug`
   - Add `hostId: string` to `RoomSnapshot` interface
   - Extend `RoomStatus` to `"lobby" | "active"`
   - Add `startRoom(code, participantId)` method calling `POST /rooms/:code/start`

### Phase D — Frontend: store + lobby

6. `frontend/src/state/roomStore.ts`
   - Add `startGame()` method: calls `api.startRoom(room.code, participantId)`,
     updates snapshot on success

7. `frontend/src/pages/LobbyPage.tsx`
   - Add polling `useEffect`: `setInterval(() => roomStore.fetchRoom(), 2000)` on mount;
     clear interval in cleanup function
   - Navigate to `/game` when `room.status === "active"` (detected via poll)
   - Show host badge: compare each `participant.id === room.hostId`
   - Gate Start Game: visible only when `participantId === room.hostId`;
     enabled only when `participants.length >= 2`
   - Wire Start Game button to `roomStore.startGame()`, then navigate to `/game`

## Testing Strategy

- Unit tests for `startRoom()` in `backend/src/services/roomStore.test.ts`:
  covers success, not-host rejection, insufficient-players rejection, not-found.
- Schema validation tests for `startRoomSchema` in `backend/src/api/schemas.test.ts`.
- Manual multi-tab validation following `quickstart.md` scenarios A–F.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Poll cleanup missed on unmount | Return cleanup from `useEffect`; verify via Network tab |
| Guest sees stale status after host starts | Poll interval ≤2s; navigate on `status === "active"` check |
| Race: host clicks Start, poll fires simultaneously | Server is authoritative; idempotent if room already `"active"` |
| Name validation differs FE vs BE | Both trim + min(1); Zod on BE, string check on FE |
